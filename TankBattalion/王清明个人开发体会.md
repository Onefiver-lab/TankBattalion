## 一、项目概述

本项目是一个基于 Qt6 / QML / C++23 开发的坦克大战游戏，支持单人闯关、双人合作、PVP 对战三种游戏模式，配有四档难度（简单/中等/困难/地狱）、存读档、暂停、粒子特效和暗色主题 UI。项目采用 MVC 架构，C++ 后端负责游戏逻辑，QML 前端负责界面渲染。

## 二、我的工作任务

我在项目中承担了以下核心开发工作：

### 2.1 搭建 C++ 核心类体系统

**提交信息**：`增加了bullet,gamecontroller,tank.gameobject类`

这是我最早期的开发工作，奠定了整个项目的后端架构基础：

- **GameObject 基类**：定义了所有游戏对象的公共属性——位置坐标、朝向方向、碰撞箱大小、激活状态。通过纯虚函数 `update()` 规范了子类的帧更新接口，使用 `Q_PROPERTY` 宏将属性暴露给 QML 前端绑定。
- **Tank 类**：继承自 GameObject，实现了坦克的全部行为逻辑。区分玩家坦克和敌人坦克，玩家由键盘控制移动和射击，敌人由 AI 驱动（定时随机改变方向和射击）。包含 HP、弹药、速度等属性，以及 `takeDamage()`、`fire()` 等方法。
- **Bullet 类**：继承自 GameObject，表示子弹。记录发射者身份（玩家1/玩家2/敌军），按方向飞行，超出边界后自动销毁。
- **GameController 类**：游戏核心控制器，管理所有游戏对象的生命周期。负责 16ms 间隔的游戏主循环（约 60 FPS）、矩形碰撞检测、胜负判定。通过 `Q_INVOKABLE` 暴露给 QML 调用。

这一阶段的工作确立了项目的 MVC 分层架构：C++ 后端为 Model + Controller，QML 前端为 View，通过 Qt 的元对象系统（信号槽、Q_PROPERTY）进行通信。

### 2.2 实现可操作的坦克大战界面

**提交信息**：`实现了真正可以操作、带有游戏舞台和键盘控制的坦克大战界面`

在核心类体系搭建完成后，我实现了完整的游戏可玩性：

- **键盘控制系统**：在 BattleField.qml 中实现了 `Keys.onPressed` / `Keys.onReleased` 事件处理，支持 WASD 移动和空格射击，方向键和回车作为玩家2的操作。

- **地图系统**：MapManager 实现 15×20 网格地图，支持砖墙（可击毁）、钢墙（不可破坏）、空地三种地形，提供碰撞检测和子弹击中处理。
- **碰撞检测**：在游戏主循环中实现了矩形相交检测——子弹 vs 墙壁、子弹 vs 坦克、坦克 vs 墙壁，碰撞后回退位置防止穿墙。

## 三、开发心得体会

### 3.1 Qt 元对象系统的理解与应用

在搭建 C++ 核心类体系时，我深入理解了 Qt 元对象系统的作用。通过 `Q_OBJECT`、`Q_PROPERTY`、`Q_INVOKABLE` 等宏，C++ 对象的属性和方法可以直接在 QML 中访问和绑定，这大大简化了前后端通信。例如 GameController 的 `bullets`、`enemies` 属性通过 `Q_PROPERTY` 暴露后，QML 的 Repeater 可以直接绑定并自动刷新。

### 3.2 游戏循环与帧时间管理

实现游戏主循环时，我学习了使用 `QElapsedTimer` 计算每帧的实际 deltaTime，而不是固定步长。这样可以适应不同设备的帧率。同时设置了 50ms 的 deltaTime 上限，防止窗口拖拽等卡顿场景下坦克穿墙。

### 3.3 碰撞检测的设计思路

碰撞检测采用矩形相交（`QRectF::intersects`），简单高效。关键设计是"先记录旧位置，碰撞后回退"——坦克移动前保存旧坐标，移动后检测碰撞，若碰撞则恢复旧坐标。这避免了坦克嵌入墙壁的问题。

### 3.4 存档系统的序列化设计

存档系统我选择了 JSON 格式而非二进制，好处是可读性强、便于调试。通过 `QVariantMap` 作为中间载体，将游戏状态序列化为 `QJsonObject`，再写入文件。恢复时反向解析，重建所有游戏对象。这个设计让我理解了对象序列化/反序列化的完整流程。

### 3.5 从 MouseArea 到 TapHandler 的迁移

试卷要求不使用 MouseArea，改用 input_handler。在实际迁移过程中，我发现 `TapHandler` 相比 `MouseArea` 有几个区别：`TapHandler` 不占用布局空间（不是 Item 子类），通过 `onTapped` 而非 `onClicked` 处理点击，hover 检测需要配合 `HoverHandler`。这次迁移让我更深入理解了 Qt Quick 6 的输入处理器架构——它将输入处理从 Item 树中解耦，更灵活也更符合现代设计理念。

### 3.6 团队协作与版本控制

项目中有多位同学参与开发，通过 Git 进行版本控制。可以看到团队成员分别负责不同的功能模块。在这个过程中，我学会了如何在团队协作中保持代码风格一致、合理拆分提交、编写清晰的提交信息。

### 3.7 UI 设计的实践

美化 UI 时，我学会了在 QML 中通过渐变、边框、阴影、动画等手段提升视觉质感。暗色主题的选择让游戏画面更聚焦，粒子特效让爆炸场景更有冲击力。血条的绿/红变色和动画过渡让玩家状态一目了然。

## 四、遇到的问题与解决方案

### 4.1 EndDialog "再来一局"按钮无效

**问题**：点击"再来一局"后对话框消失，但游戏没有重新开始。  
**原因**：对话框关闭后键盘焦点留在了按钮上，没有回到战场。  
**解决**：在 `onRestartRequested` 信号处理中添加 `battleField.focus = true`，将焦点还给战场。


### 4.2 Q_INVOKABLE 与前向声明的编译错误

**问题**：将 `setSettingsManager` 加上 `Q_INVOKABLE` 后，编译报错 "Meta Types must be fully defined"。  
**原因**：`Q_INVOKABLE` 要求参数类型完整定义，而代码中只用了前向声明 `class SettingsManager`。  
**解决**：在 gamecontroller.h 中 `#include "settingsmanager.h"`，提供完整类型定义。
